# Métricas operativas privadas

`GET /api/ops/metrics` está oculto (`404`) cuando `METRICS_TOKEN` falta o no tiene entre 32 y 1024 caracteres. Con secreto válido requiere `X-Metrics-Token`; credencial ausente/incorrecta devuelve `401`. La respuesta usa `Cache-Control: no-store`. Es un secreto de servidor, separado del JWT de la app.

Los contadores e histogramas viven sólo en memoria del proceso y arrancan en cero cada vez que inicia. Las duraciones usan buckets fijos en ms (10, 50, 100, 250, 500, 1000, 5000, 30000 y overflow); se publican conteo y suma, no percentiles. Nunca se guardan muestras individuales, rutas variables, query strings, cuerpos, imágenes, IDs, tokens o usuarios. El middleware HTTP cuenta únicamente `POST /api/cards/identify-visual`, incluyendo rechazos de guardas y validación. Un cierre prematuro se cuenta como `aborted` sin atribuirle un status terminal; el resto se agrupa por clase HTTP y cuenta además 400/401/503 explícitos. Las admisiones de inferencia se cuentan en el servicio con causas explícitas; `busy` no se deduce de un HTTP 503. `started` sólo se incrementa tras pasar validación y disponibilidad; `completed`/`failed` y `worker_duration_ms` describen ese trabajo iniciado. `inference_duration_ms`, `index_duration_ms` y `model_duration_ms` reflejan los campos del worker. `cold_model_duration_ms` sólo se registra cuando el worker marca el resultado frío. `warmup_duration_ms` mide la preparación inicial del worker hasta ready/fallo, no el tiempo aislado de carga del modelo.

La cola expresa `pending` y `processing` actuales, ambos con cero cuando no hay filas. Edad es desde `createdAt` del job más antiguo por estado y se calcula contra un único corte de muestreo. `retries` suma `max(attempts - 1, 0)` para jobs activos: `attempts` cuenta reclamos reales, por lo que un primer reclamo no es reintento; trabajos completados o descartados ya no aparecen. El query usa un cliente Prisma independiente con límites de conexión, socket y statement acotados iguales al probe de readiness; el resultado se comparte durante un segundo y el tiempo máximo de espera HTTP es dos segundos. Una consulta lenta se mantiene como singleflight hasta asentarse para evitar multiplicar trabajo. Si falla o vence el plazo, se devuelve `queue.state=unavailable` sin detalles. Redis sólo expone el estado agregado ya mantenido por `RedisService`; no expone su URL ni el mensaje de error.

No se agregan eventos de participantes, almacenamiento persistente ni proveedor externo. La lectura de métricas es best effort y no interviene en respuestas del escáner.

Para consumirlo, el monitor envía el secreto configurado como encabezado `X-Metrics-Token` únicamente por una conexión privada o HTTPS. No incluirlo en URLs, evidencia, configuración pública del frontend o logs. `queue.sampledAt` identifica el corte cacheado; una lectura nueva de Redis no cambia ese corte. Los histogramas aún sin observaciones se omiten, mientras todos los contadores se publican en cero al inicio. No hay endpoint de reset: reiniciar el proceso abre otra ventana. Para sumar varias instancias, conservar la ventana de cada proceso y no sumar gauges de la misma cola compartida.
