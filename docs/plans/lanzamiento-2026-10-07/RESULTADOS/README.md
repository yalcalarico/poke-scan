# Evidencia de ejecución

Carpeta de entregas y resultados. Ya contiene especificaciones/protocolo y [estado del coordinador](ORQUESTACION-ESTADO.md); esos documentos no acreditan entrevistas, benchmarks, contratos implementados ni cobros.

Usá los nombres definidos por cada ID, por ejemplo `UX-01-flujo.md` o `RES-03-protocolo.md`. Si una tarea entrega código, guardar aquí un informe breve y enlazar los archivos/pruebas; no duplicar el código fuente.

Cada informe debe incluir:

- ID, responsable, fecha y estado; versión/commit de referencia si corresponde.
- Entrada recibida y dependencia todavía pendiente.
- Qué se entregó, referencias y decisión/contrato usado.
- Aceptación comprobada con prueba, muestra, fuente o medición real; entorno y denominadores.
- Qué no se comprobó y qué falta para cerrar.
- Handoff a otra área si es necesario, sin ampliar el encargo original.

No guardar secretos, datos personales, fotos de consulta o material de investigación privado en esta carpeta. Una plantilla vacía no es evidencia y no marca la tarea como completada. El coordinador consolida el estado en [el registro](../REGISTRO-TAREAS.md).
