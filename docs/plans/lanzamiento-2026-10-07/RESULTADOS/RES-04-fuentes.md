**Fecha de revisión:** 2026-10-08 (UTC−03:00)  
**Responsables:** Luna · entrega inicial; Sol HIGH · revisión y correcciones documentales  
**Estado:** investigación documental y revisión Sol HIGH completas. RES-04 cumple su aceptación documental; registro/planes a cargo de coordinación. No acredita permisos comerciales, procedencia del ONNX ni precio argentino homologado. [Revisión y evidencia](RES-04-review.md).

## Resultado ejecutivo

El repositorio confirma el split actual: el catálogo se espeja desde `pokemontcg.io`; los precios actuales se consultan desde TCGdex y se registran como mercado TCGplayer en USD. El límite de 1.000 solicitudes diarias y 30 por minuto se conserva como restricción local del origen de catálogo; no se atribuye ese límite a TCGdex. La documentación upstream del Pokémon TCG Data/API ahora identifica el servicio como legado y señala cierre de API para el **1 de marzo de 2027**. Esto eleva el riesgo de continuidad del catálogo; no es una recomendación para cambiar ahora la PK canónica ni para empezar una migración dentro de RES-04. [Pokémon TCG Data, estado/deprecación](https://github.com/PokemonTCG/pokemon-tcg-data) · [documentación de autenticación y aviso de deprecación](https://docs.pokemontcg.io/getting-started/authentication/).

La base de datos del catálogo de TCGdex declara licencia MIT, pero eso por sí solo no despeja los derechos de ilustraciones de cartas, marcas, feeds de terceros ni cada campo derivado. TCGplayer exige aprobación escrita para usar su API y restringe usos competitivos y la combinación de datos de precios. Scrydex publica tiers desde $29/mes (USD inferido por contexto del proveedor; no ISO en pricing), pero sus términos, cuotas efectivas y derechos de uso para el caso de PokéScan requieren evaluación contractual antes de presupuestarlo. [TCGdex cards-database](https://github.com/tcgdex/cards-database) · [TCGplayer API Terms](https://help.tcgplayer.com/hc/en-us/articles/360061115874-TCGplayer-API-Terms-Conditions) · [Scrydex pricing](https://scrydex.com/pricing).

La identidad local verificable del modelo es `backend/.scanner-models/dinov2-small-int8.onnx`, SHA-256 `c179f8f7f592449c4c1bca4cd124a7538021428c5ffb89afde9503935b197efb` (24.446.700 bytes, recalculado en esta revisión); el preprocesado tiene hash `8170121eafd1c4dd3122475255b0c6bb811cc598d38abcaf34ac9dd5ca483708` en el reporte histórico del 6/10. No se encontró en la inspección selectiva una cadena versionada que una checkpoint/revisión/licencia con la exportación/cuantización de ese binario. El [MODEL_CARD oficial de DINOv2 S/B/L/g](https://github.com/facebookresearch/dinov2/blob/main/MODEL_CARD.md) comprende modelos con y sin registers y declara Apache 2.0; las fichas específicas [small base](https://huggingface.co/facebook/dinov2-small) y [small con registers](https://huggingface.co/facebook/dinov2-with-registers-small) también muestran Apache 2.0 (el texto de esas fichas declara autoría Hugging Face). La licencia [FAIR de Cell-DINO](https://github.com/facebookresearch/dinov2/blob/main/LICENSE_CELL_DINO_MODELS) corresponde a otra familia incorporada al repositorio: no contradice ni reemplaza la licencia de DINOv2 general. Esto corrige la atribución inicial de Luna. Ninguna ficha demuestra qué checkpoint produjo el ONNX local: su licencia concreta sigue **no verificada**, sin inferir permiso ni prohibición comercial por el nombre.

La muestra local no alcanza para una referencia de precio argentino homogénea: varias cifras son valores internacionales convertidos, órdenes de compra o listings en condiciones distintas; no se halló una misma carta con impresión, variante, idioma, condición, graduación y fecha completas en cuatro tiendas locales. Por lo tanto, este informe no propone una estimación ARS ni llama “ventas verificadas” a datos que la fuente no acredita.

### Riesgo de vigencia y posible sustitución del catálogo

La alternativa técnica más directa para explorar sin cambiar IDs es usar otro catálogo como fuente de metadatos y construir un mapeo externo por proveedor/alias, manteniendo la PK actual en IDs canónicos de PokéScan. TCGdex cubre muchos idiomas y tiene datos abiertos; Scrydex anuncia soporte activo, datos de cartas e imágenes. La cobertura exacta por carta, equivalencia de IDs, derechos de arte, costos por volumen y continuidad no se verificaron aquí. El repositorio histórico puede servir para respaldar compatibilidad o una importación histórica solo si se comprueba derecho aplicable; el aviso de que JSON permanezca disponible no otorga por sí mismo permiso comercial para redistribuirlo. Ninguna de estas opciones se recomienda como cambio de canonical PK en esta entrega.

### Lectura para la futura matriz de homologación

No se encontró una comparación argentina defendible con una misma referencia de carta que tenga a la vez ID de catálogo/impresión, set, número, variante de foil/edición, idioma, condición física, eventual grado PSA/CGC/BGS, moneda, timestamp, tipo de observación (listado, buy order, venta cerrada) y fuente primaria del intercambio. No se deben fusionar Charizard VMAX con Charizard Base #004/102, ni usar la orden de compra como venta, ni tomar un valor convertido blue como precio local observado.

Para una comparación futura, registrar una fila por observación y exigir esos campos. Si faltan, conservar el dato como “no homologable” y no rellenarlo con el promedio del set, nombre de Pokémon, variante inferida o tipo de cambio. Precio de listing informa aspiración/oferta; un buy order, disposición declarada del comprador; una venta cerrada, transacción reportada por la plataforma con calidad de origen explícita. Ninguna modalidad debe renombrarse “market price” sin definir método, cobertura y ventana.

## Handoffs

- **NEG-02:** usar estas observaciones como mapa de tipos de producto y fuentes, no como evidencia de demanda o precio Pro. Costos de Scrydex son montos publicados con $ y USD inferido, aún sin confirmar en checkout y el unit economics debe partir de escenario de uso, volumen/caché y contrato; no estimar willingness-to-pay ARS a partir de precios extranjeros. Falta una comparación local homologada.
- **NEG-03:** separar cobro de app de pagos/marketplace de cartas. Card Stash es el único P2P de esta muestra que declara pago integrado y retención para buy orders; no se verificó custodia efectiva ni funcionamiento de checkout; sus tarifas declaradas son del ejemplo de su propio sitio y no trasladables a PokéScan. Incluir obligaciones de términos/consumidor y revisión profesional cuando el dueño elija operar pagos. Sin recomendación de cobrar aquí. Recibir también el pendiente de derechos por clase de activo y la procedencia ONNX para el análisis comercial; no se crea bloqueo de investigación por falta de permiso.
- **INF-01:** upstream anuncia apagado de API el 2027-03-01; planificar due date de continuidad con margen. Consultar términos de cada fuente y conservar mapping externo; mantener PK canónica actual hasta decisión separada. El hash ONNX local está identificado, pero sin provenance y licencia auditable de weights/conversion.
- **SEO-03:** permitir copy que describa “referencia internacional convertida” o “precio de publicación/oferta” según la fuente; no decir “venta local” ni “venta verificada” para feed/estimaciones. Mostrar origen, mercado, divisa y fecha/antigüedad junto al dato. Toda comunicación sobre arte/logo Pokémon requiere validar derechos por separado.
